# mod-rc2

**Mission: a functional, source-faithful reconstruction of the Rocket Crowbar 2 (beta 1.1) server
and client game libraries as modern C++ on the halflife-updated SDK, that builds for every arch the
buildchain targets, loads in the engine, and behaves identically to the original.**

RC2 (January 2004) is a near-total rewrite of RC 1.9: it adds the forklifts and shoulder riding,
racing, five player transforms, an attribute point-buy, the shield and energy, a new grenade and
mine set, shotgun scientists and HEV suits, the crowbarang and the nuclear missile, and ships its own
client library. It still shares code with RC 1.9 (`CCrowbarRocket`, `AddToPrecachedList`).

## Method

Same as `../mod-ts` (reTS) and `../mod-rockcrowbar`: behavior parity on a modern compiler, with the
external interface (entities, keyvalues, cvars, commands, user messages, events, `rc2.ini` and the
`maps/lcs/*.lcs` configs) as the swap contract. There is no Linux build, so no symbol table: names
come from SDK 2.3 built with RC2's own compiler (VC6 12.00.8168, `scripts/vc6/`), matched byte for
byte, and by vtable position; RC2's own code has no recoverable names, so those are ours and marked
`// name ours`. `../DECOMPILE.md` section 2a has the whole method.

## This repo

A fork of `goldsrc-net/halflife-updated` branch `64bit-demo`, like mod-ts.

- `upstream` = `git@github.com:goldsrc-net/halflife-updated.git`, tracked by `main`.
- No `origin` yet. When it gets one it is a private goldsrc-net repo (`../REPOS.md`).

| Path | What |
|---|---|
| `game/rc2/` | the mod's gamedir manifest (`liblist.gam`) |
| `reference/` | the originals, provenance, and every table read from them: names, vtables, save fields, cvars, `prefs-rc2.tsv` (rc2.ini), files and gaps by link order, the work lists (`RECONSTRUCTION-<lib>.md`) |
| `reference/BASE_VIRTUALS.md`, `DEVIATIONS.md` | what RC2 added to the SDK bases; what we do differently |
| `reference/dossiers/` | the briefs (`AGENT_BRIEF.md`, `AGENT_BRIEF_CLIENT.md`), the package splits (`PACKAGES*.md`), one dossier per package |
| `dlls/rc2/`, `cl_dll/rc2/` | RC2's own files (globbed by CMake); changed stock code stays in its SDK file |
| `dlls/rc2prefs*` | rc2.ini: the key table generated by `scripts/gen_prefs.py`, the loader |
| `scripts/` | `build.sh` (buildchain; one build at a time), `check_coverage.py` (the measure: an `// orig 0x<rva>` per function; client `// orig client 0x<rva>`), the table generators, `vc6/`, `ghidra/` |
| `scripts/merge/` | helpers for merging package branches (stubs, duplicate definitions) |
| `tools/rig/` | the original (Wine, 27031) and ours (27032) side by side |

Original content: Steven's install at `/media/Data3/Projects/mods/rc2/` (beta 1.1 plus extra maps).

## Status (2026-11-07)

- **Server (rc2.dll):** all 2,468 functions to reconstruct have a counterpart, counting the code
  Ghidra's function list misses (`scripts/gaps.py`). Builds on i386 and amd64.
  `tools/rig/smoke.py` boots ours and the original side by side, changes map through three RC2 maps
  and reads RC2's cvars: the only console difference is a halflife-updated skill cvar warning
  (`reference/DEVIATIONS.md`). Not played yet.
- **Client (client.dll):** 1,158 of 1,466 functions (78%); the rest is template and
  compiler-generated code (c1's dossier lists it). Builds on i386 (amd64 has no 64-bit VGUI). The
  packages' cross-references are reconciled by original address (`reference/dossiers/w3-reconcile.md`).
  Never run in an engine.
- No TEMP STUBs left in the tree. The weapon files in dlls/ are one source for both libraries.
- The original's bugs are in `reference/ORIGINAL_BUGS.md`; its crashes are guarded (RC 1.9's
  policy, `reference/DEVIATIONS.md`). Server docs: `docs/SERVER.md`, `GAMEPLAY.md`, `RC_INI.md`
  (generated by `scripts/rc2ini_doc.py`).
- Running: the audit of the 400 stock functions (byte-identical to SDK 2.3 in RC2) that still carry
  halflife-updated's changes (`reference/audit/BRIEF.md`, five packages a1-a5). Steven decided to
  put SDK 2.3's behavior back wherever it shows in multiplayer; RC 1.9 gets the same pass after.
- Not yet: playing ours against the original with our client.
