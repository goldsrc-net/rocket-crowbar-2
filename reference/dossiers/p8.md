# p8: rc2.dll .text 0xd3440-0xece52

The work was done in three parts: squeak, subs, talkmonster, teamplay_gamerules, tentacle and
triggers (main); the player transforms (fork A); tripmine (fork B). Each part has its own sections
3-8 below.

## 1. Scope

Original files: the end of squeakgrenade (CSqueak's RC2 code), subs, talkmonster, tassassin, tbat,
tcontroller, teamplay_gamerules, tentacle, theadcrab, thoundeye, transform (its `__FILE__` string
names it), triggers, tripmine. The four t*.cpp names come from the event files
(events/tassassingun.sc and so on), so they are ours but well founded.

Files written: dlls/rc2/squeak.cpp, tassassin.cpp, tbat.cpp, tcontroller.cpp, theadcrab.cpp,
thoundeye.cpp, transform.cpp, p8_needs.h, p8_needs_transform.h, p8_needs_tripmine.h, p8_stubs.cpp,
p8_stubs_transform.cpp, p8_stubs_tripmine.cpp.

Files changed: dlls/subs.cpp, talkmonster.cpp, talkmonster.h, teamplay_gamerules.cpp, tentacle.cpp,
triggers.cpp, tripmine.cpp. Shared files, only inside p8 blocks: cbase.h, basemonster.h, player.h,
weapons.h. Shared file outside a block: squeakgrenade.cpp (p7's) has its stock server
CSqueak::PrimaryAttack/SecondaryAttack under `#ifdef CLIENT_DLL` (the server's live in
dlls/rc2/squeak.cpp), plus a comment on WeaponIdle (0xd4250, stock). Merge note: the p7 and p8
edits to squeakgrenade.cpp and to CSqueak in weapons.h meet there.

UTIL_GetLocalPlayer goes back to edict 1, which matters because RC2 is multiplayer; the
trigger_hurt dead-player heal test is removed; the talker push interrupt-mask test is removed.

## 4. Classes

- **CSqueak** (CBasePlayerWeapon, size 0xf0). Stock: m_fJustThrown at +0xdc and m_usSnarkFire at
  +0xec. RC2's members, read from code with names ours: m_iSnarksDeployed (+0xe0),
  m_iCamsDeployed (+0xe4), m_flNextWeaponSync (+0xe8) and m_usSnarkFire2 (+0xee, the snark cam's
  event). CSqueak::Precache (p7) has to fill m_usSnarkFire2.
- **CBasePlayerWeapon**: two of RC2's 8 added bytes are m_flNextTertiaryAttack (+0xb0) and
  m_flNextQuaternaryAttack (+0xb4). They are named from rc2.ini's `<Mode>RefireTertiary` and
  `RefireQuaternary` keys, and CanAttack in ItemPostFrame gates on them.
  The slot layout comes from all 17 weapon vtables:
  - slots 105-108 are Primary, Secondary, TertiaryAttack and QuaternaryAttack;
  - 109 is Reload, 110 WeaponIdle, 111 RetireWeapon, 112 ShouldWeaponIdle, 113 UseDecrement
    (SendWeaponAnim calls slot 113);
  - 114 is UpdateWeaponSync, the first thing ItemPostFrame calls each frame;
  - 115 is ReadWeaponSync(pbuf, size), the client's reader built into the server.

  This contradicts BASE_VIRTUALS.md's "two after PlayEmptySound". The weapons package (p9) owns
  the final names.
- **CTalkMonster**: the 4 bytes before m_useTime (+0x308) are a 19th sentence group, m_szGrp[18].
  barney's TalkInit sets it to "BA_MINE". They are declared as TLK_MINE in the TALKGROUPNAMES enum,
  so this is an enum entry rather than a member block. IsFollowing (inline, talkmonster.h) uses
  IsActivePlayer.
- **CTentacle** (0x300): the stock members, no RC2 additions.
- **CBaseEntity**: the byte at +0x66 is m_bFrozen (name ours). CFreezeTimer sets it to 1, and
  talkers and the player's weapons test it. Fork A added m_bAntiFriction at +0x67. Both bytes sit
  inside cbase.h's `int m_iRC2Base64`, which the merge has to split.
- **CBaseMonster**: slot 147, ScalePitchShift() (name ours). Its default at 0x74d0 maps pev->scale
  to a pitch offset. A TEMP STUB returns 0, and the client gets an inline 0.
- **CBasePlayer**: m_iDrivenEntIndex (+0x69c), the entity index of what the player drives or
  rides. Fork A's transform members follow it (Part 2).

## 7. Behavior worth testing

- Snarks:
  - the deploy cap (SnarkMaxDeployed);
  - the mini grunt on attack2;
  - a snark cam stuck to a wall on the third attack;
  - looking through it on the fourth;
  - the HUD counts (WeaponSync, every 0.5 s).
- Talkers:
  - a frozen scientist or barney neither talks nor follows;
  - a shrunk one flees from normal-size things and talks at a higher pitch;
  - they won't follow non-player classes.
- trigger_changelevel in multiplayer with sv_noexit 1: touching or using it kills (50000,
  ALWAYSGIB), whoever touches it. In deathmatch with sv_chglevel 1: it changes level with no
  landmark (see bug below).
- Teamplay team change: kill damage 50000; the scoreboard reads RC2's ScoreInfo layout.
- Tentacle: shield-absorbed hits, and the no-damage hit that doesn't start the 0.5 s wait.
- trigger_push ignores entities with RC caps bit 2; trigger_hurt, trigger_gravity, autosave and
  cdaudio only respond to active players.
