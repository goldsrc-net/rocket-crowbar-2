## Package-wide merge notes

- GetRCCaps/GetRCCaps2 (cbase.h slots 75, 76) take `(int, CBaseEntity*)`, but every call
  site in the mines passes an entity pointer first. Forks B and C cast with
  (int)(intptr_t), which truncates on amd64. The first parameter should become CBaseEntity*.
- Every original factory calls RC 1.9's AddToPrecachedList (0xf5a20); the tree's
  LINK_ENTITY_TO_CLASS doesn't, so the factories carry VERIFYs.
- 0xf2fe0 is RC2's changed UTIL_IsValidEntity (adds pvPrivateData, nonzero offset and a
  connected-players bitmask at 0x101af2a8 for player slots); the SDK one is called.
- CBaseEntity's m_iRC2Base54 is a float (time of the last ApplyExternalForce);
  m_vecRC2Base58 is the egon tractor point; m_iRC2Base64 is four bytes used one by one
  (+0x64 tractored, +0x65 cleared with it, +0x66 and +0x67 player states the riding and race
  code test). Accessed as ((unsigned char*)&m_iRC2Base64)[n] / RC2_BASE_BYTE().
- Weapon slots, as read here: 105 Primary, 106 Secondary, 107 Tertiary, 108 Quaternary,
  109 Reload, 110 WeaponIdle, 111 RetireWeapon, 112 ShouldWeaponIdle, 113 UseDecrement,
  114 WeaponFrame, 115 ReadWeaponState (matches p3's declarations; fork C read the RPG's
  109-113 the same way). BASE_VIRTUALS.md's "two after PlayEmptySound, two after
  RetireWeapon" should be corrected by the weapons package.
- User messages used, with TEMP STUB globals: CLTE (playerride.cpp), RCCFG (rc2prefs.cpp),
  RaceStat (racecontroller.cpp), PullerCtrl (p6stubs.cpp).
- pm_shared reads rc2.ini directly; the client build gets an all-zero g_rc2PrefValues and
  neutral hook stubs under CLIENT_DLL until client.dll is reconstructed.

### rc2.ini: what the record's fields mean (answers rc2prefs.h's old VERIFYs)

The "rccfg findkey" listing (0xaf890) prints both the type and the flags by name, so these
are the original's own words.

```
type  name (as printed)              storage  notes
0     FLOAT (-3E38...3E38)           float
1     SMALL FLOAT (0...655.35)       float    clamped to 0..655.35 on parse; sent to clients as WRITE_SHORT(value*100)
2     DOUBLE (-1E308...1E38)         double   network send writes the low dword twice (bug)
3     INT (-2E9...2E9)               int
4     SHORT (-32767...32767)         short    parse clamps to -32767..32767
5     UNSIGNED SHORT (0...65535)     short    parse clamps to 0..65535, printed unsigned, flag clamps read it signed
6     BYTE (0...255)                 byte
7     BOOL (T/F)                     byte     "true", "yes" (any case) or a nonzero number; written "true"/"false"

flag        name                 effect
0x1         POS_ONLY             < 0 -> 0
0x2         THREE_DIGITS         clamp 0..999
0x4         NOT_ZERO             0 -> 1
0x8         GREATER_THEN_ONE     < 1 -> 1
0x10        ZERO_TO_ONE          clamp 0..1
0x20        NEGATIVE_ONE_TO_ONE  clamp -1..1
0x40        FOUR_DIGITS          clamp 0..9999
0x40000000  REGISTER_ITEM_INFO   a change re-reads ItemInfo of the 14 stock weapons
0x80000000  NETWORK_SYNC         sent in user message RCCFG (short index + value; 0x7fff = reset to defaults)
```

Clamp order in the parser: POS_ONLY, THREE_DIGITS, ZERO_TO_ONE, NEGATIVE_ONE_TO_ONE,
FOUR_DIGITS, GREATER_THEN_ONE, NOT_ZERO. The shipped rc2.ini (/media/Data3/Projects/mods/rc2)
has exactly the table's 1,113 keys, all matching (checked with a Python model of the
loader's matching rules).

"rccfg" commands (0xb0050), case-sensitive: listheadings, listkeys heading page (20 a page),
findkey partialkey [partialheading] (22 lines max) for everyone; setkey heading key value and
reset need CBasePlayer admin level >= 1 or sv_tempadmins (0x1160); save [file], savediff
file, load [file] need level >= 2. Files are <gamedir>/<name>, default the rccfgfile cvar.

### Shoulder riding

"ride" (the command's dispatcher is in another package): climbs on the player whose center is
within 64 units and most nearly in front (flat dot >= 0), who is an active player, not
transformed, not shrunk, not on someone, with a free shoulder, and whom gamerules slot 57
allows (multiplay: mp_riding nonzero and the target's "allowriding" userinfo nonzero).
Costs 40 energy; "ride" again gets off for 20. Rider: SOLID_NOT, view_ofs z 11, pev->owner =
the ridden player; pm_shared moves the rider through PM_GetRideInfo/PM_GetEntityBox. Getting
off tries six spots around the ridden player's center (+-36 x, +-36 y, +-42 z) with a 1-unit
human-hull trace.
