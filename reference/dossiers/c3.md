# c3: client.dll .text 0x71ad0 to 0x9b445

## Scope

The second half of the run "new: cdll_int .. com_weapons" (PACKAGES-client.md "## c2" lists the
whole run; 0x50060-0x71ad0 is package c2's). It is one translation unit of the original: RC2's
client temp effects, the "CLTE" user message. c2 has the framework (the effect base class, the
600-slot effect table, the dispatcher at 0x510b0, the per-frame loops, drawing helpers and two
point-list classes); c3 has the effects for CLTE types 0x26 to 0x49, each a class with a factory
the dispatcher calls, plus two methods of c2's shield effect (0x25) and the compiler's
out-of-line copy constructors at the end of the run.

Written here, all new, all in `cl_dll/rc2/` (globbed by cl_dll/CMakeLists.txt):

- `c3_needs.h`: what c3 uses from other packages (c2's base class CClientTent, the effect table,
  CRC2Trail, CRC2Particles, the ellipsoid draws, globals, c2's CShieldTent); every name ours.
- `c3_tents.h`: the 37 factories, for c2's dispatcher.
- `c3_stubs.cpp`: TEMP STUB definitions of everything c3 uses from other packages.
- The effects: shield_tents.cpp, shrinker_tents.cpp, egontractor_tent.cpp, nuke_tents.cpp,
  blastsphere_tent.cpp, implodercharge_tent.cpp, imploder_tents.cpp, freeze_tents.cpp,
  gravgrenade_tents.cpp, shockring_tents.cpp, suckgrenade_tents.cpp, antifriction_tents.cpp,
  ultima_tent.cpp, energyblast_tents.cpp, charge_tents.cpp, tripminezap_tent.cpp,
  roachwalk_tent.cpp, snarktrail_tent.cpp, forklift_tents.cpp, transform_tents.cpp,

No shared file was touched.

### How it was read

36 of the range's 169 functions are not in files-client.tsv or the shared decompile: Ghidra never
defined them, since they are reached only from vtables through the incremental-link thunks (most
effects' Think, DrawTransparent and EntityGone). They were found as uncovered code between the
listed functions and decompiled in a private copy of the Ghidra project (copied from
recovered/ghidra into the scratchpad, so the shared lock was never taken), where the thunks were
also marked as thunks, callee signatures committed and the engine interfaces (cl_enginefunc_t,
triangleapi, efx, event API, from SDK 2.3's headers) typed onto gEngfuncs. The shared decompile
drops every computation whose result goes to an untyped thunk call, and neither decompile can
follow MSVC's Vector-by-value arguments (copy-constructed onto the stack), so every call passing
Vectors, and every spot where the two decompiles disagreed, was read off the disassembly. The
scripts are in ~/stignored/rc2-client-re (dis.py: annotated disassembly; Retype.java and
ApplyApi.java: the private Ghidra pass; missed.py: uncovered code in a range). Because the 36 are
not in files-client.tsv (and client.dll has no gaps-client.tsv), check_coverage can't count them;
they carry `orig client` tags all the same. The work was split over five forks of this agent by
address range; their sections are below.
