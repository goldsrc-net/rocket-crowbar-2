## Scope

The original's files (labels in `reference/files-rc2.tsv`, PACKAGES.md "## p9"): the run after
tripmine, turret, the run after turret, util, the virtual hull run, voice_gamemgr, the vote run,
`infodecal` (the run before world), xen, the run before zombie, zombie. The C runtime runs at the
end of .text are nobody's (`new: libcmt:*`, which check_coverage still lists: 0 of 2 etc.).

Written or touched here:

- `dlls/turret.cpp`, `dlls/util.cpp`, `dlls/util.h`, `dlls/xen.cpp`, `dlls/zombie.cpp`,
  `game_shared/voice_gamemgr.cpp`, one tag line in `dlls/world.cpp` (infodecal).

  `dlls/rc2/vote.cpp`, `dlls/rc2/p9_needs.h`, `dlls/rc2/p9_stubs.cpp`.
- Shared: `dlls/weapons.h` and `dlls/player.h` in `// p9 needs:` blocks (below).

weapons.cpp and world.cpp were first assigned to p9 by the coordinator's brief and later
reassigned to p3 (which owns them per PACKAGES.md and has merged them). p9's reconstruction of
both was taken out of the worktree. Where p9's reading of them may help the merge it is in

## Original bugs

- UTIL_IsValidEntity (0xf2fe0): `!g_iRC2ClientBits & (1 << (i - 1))`: with no client bits set,
  client slot 1 is invalid; otherwise every client slot is valid. Kept.
- AddToPrecachedList (0xf5a20): the duplicate check tests the name for NULL instead of comparing,
  so names are added again until the 512 slots fill; strcpy without bounds (128-byte rows). Kept.
- UTIL_ClearEntityMarks (0xf4c50) drops the sets without freeing; UTIL_PushEntityMarks leaks the
  set it overwrites at the top level. Kept.
- UTIL_RC2WaterDischarge (0xf4e70): the shield's result is only tested; the full damage is dealt.
- UTIL_RandomEntityByClassname (0xf31a0): RANDOM_LONG(0, count) can pick one past the end, then
  the search wraps (up to 1000 tries). Kept.
- UTIL_RC2TimedEvent (0xf5d80): no NULL check on the created entity. Kept.
- Tripmine MineAttack: the limit test is "greater than", so one mine more than MaxOut goes out.
- votekick (0xf89d0): the second "already voted" bit is the caller's again, so the player being
  kicked may vote; the kick command passes the entity index where banid wants the user id
  ("banid 10 #<entindex> kick").
- VoteThink (0xf8280): fails a vote once the undecided players (the caller is among them, never
  having a yes or no bit) are fewer than the votes needed. Kept (VERIFY above).

## Notes on p3's files (weapons.cpp, world.cpp)

p9 had reconstructed both before the reassignment; the readings agree with p3's merged ones on
the virtuals and members. Points worth a second look in p3's version:

- SecondaryAmmoIndex (0xfb3a0) is `or eax,-1; ret`: RC2 returns -1 (SDK 2.3's bug, so
  m_rgAmmo[-1] = m_pLastItem is read); halflife-updated returns m_iSecondaryAmmoType.
- AttemptToMaterialize (0xfa550) adds gpGlobals->time to FlWeaponTryRespawn's result (SDK 2.3's
  bug); halflife-updated doesn't.
- ExtractAmmo (0xfb650): the uninitialized return holds pWeapon (true) when the weapon has no
  primary ammo; secondary uses m_iDefaultAmmo2 and keeps the primary result when it succeeded.
- CRpgRocket's save table (0x142510) has only m_flIgniteTime.
- RC2's GiveAmmo (CBaseEntity slot 24) takes a fourth argument (pops 16 bytes; CWeaponBox's
  GiveAmmo overrides it virtually), always 0 in weapons.cpp.
- DefaultTouch/ammo DefaultTouch/CWeaponBox::Touch also require the player's member at +0x10f8
  to be 0 (p3 calls it m_iRC2PlayerForm; CopyToBodyQue copies it to playerclass).
- RandomItemOfKind (0xf96b0) calls UTIL_CountEntitiesByClass("item_longjump") and ignores it;
  that function counts over all entities (gpGlobals->maxEntities), not clients.
