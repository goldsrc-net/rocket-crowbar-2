## For DEVIATIONS.md

- **The dedicated server's `servercfgfile` is run by the engine, not the game rules**
  (`CHalfLifeMultiplay` constructor, orig 0x7df80). Today's engine execs it once per map itself;
  the original's game code also did, which would run it twice. A listen server still runs
  `lservercfgfile` from the game, as in the original.
- Under "Crashes in the original": **`func_breakable` material 9 (`matNone`) precaches and sounds
  as wood** (`dlls/func_break.cpp` `Precache`, `DamageSound`). KeyValue lets it through, and the
  original used an uninitialized model name and sound list for it.
- Under "Crashes in the original": **`CHGrunt::CheckMeleeAttack1` fails with no enemy**
  (`dlls/hgrunt.cpp`); the original read an uninitialized monster pointer.
- Under "Crashes in the original": **mapcycle tokens are copied bounded**
  (`dlls/multiplay_gamerules.cpp` `ReloadMapCycleFile`); a long map name or rule string in
  `mapcycle.txt` overran the original's buffers.
- Under "Crashes in the original": **`CSoundEnt::ISoundsInList` counts 0 for an unknown list
  type** (`dlls/soundent.cpp`) instead of walking an uninitialized index.
- **Beams keep their attachment when their entity is set again** (`dlls/effects.cpp`
  `CBeam::SetStartEntity`, `SetEndEntity`). The original shifted the attachment bits out; that only
  shows after a save is restored.

## Odd

- halflife-updated's `CFlyingMonster::ChangeYaw` computes `speed = 220 * delta` and then passes
  `220.0 * speed`, so its roll step was 220 times SDK 2.3's, not just frame-rate independent.
  `CIchthyosaur::ChangeYaw` (`dlls/ichthyosaur.cpp`, package a3) has the same code. After the revert,
  `CFlyingMonster::m_flLastZYawTime` (`dlls/flyingmonster.h`, shared header) is unused; it is left
  in place, it is not in the save table.
- The button reverts bring back halflife issue #1681: a pusher thinks on `pev->ltime`, so with
  `gpGlobals->time` a sparking button's next spark comes late by the gap between the two
  (halflife-updated's changelog calls it "buttons not sparking in multiplayer"). It is RC2's
  behavior, so it stays.
- `CBeam::SetStartEntity`/`SetEndEntity` would also differ for an `env_beam` or `env_laser` whose
  map sets `sequence` or `skin` to 4096 or more (`CLightning::BeamUpdateVars` calls them each
  update). No stock map does that; classed `sp`.
- `CBlood::BloodPosition`: halflife-updated's `UTIL_PlayerByIndex(1)` is NULL for a slot 1 edict
  that isn't free but has no private data, where SDK 2.3 used that edict's origin. That window
  (mid-connect) is too short to matter; classed `style`.
- `stock_drift.py --diff` prints the raw unified diff, mostly restyling. Triage helpers:
  `~/stignored/rc2-tools/audit/normdiff.py` (per-line normalized diff of each row's body) and
  `showbody.py` (both bodies side by side), with `extract.py` to cut one package's rows out of the
  full `--diff` output.
