# a4: halflife-updated's drift in RC2's stock functions

Files: `a4.files`. Rows: the 87 of `sdk-drift.tsv` in those files, then 10 more stock functions in
the same files that `stock_drift.py` doesn't report (see "Odd" below). Each was read in both trees
(ours and `build-vc6/singleplayer`), not only in the diff.

Classes as BRIEF.md. One `play` revert (`CScriptedSentence::AcceptableSpeaker`); no `unclear`.

## The play revert

`CScriptedSentence::AcceptableSpeaker` (dlls/scripted.cpp): the `else` branch that accepted a
non-monster speaker whose `IsAllowedToSpeak()` is true is gone, with the comment
`// SDK 2.3's (stock in RC2); halflife-updated also let a non-monster that IsAllowedToSpeak
(func_button) speak the sentence`. In halflife-updated only CBaseButton (and the cyclers) return true
there. With SDK 2.3, and now ours, a scripted_sentence whose `entity` names a button finds no speaker and
retries every `repeat + 0.5` seconds; in halflife-updated it played the sentence from the button and fired
its targets. FindEntity, FindThink and StartSentence keep their CBaseToggle types: monsters are
CBaseToggles, so they return and play exactly what SDK 2.3's did.

## For DEVIATIONS.md

Under "Crashes in the original", server:

- **A hornet without an owner does no damage** (`dlls/hornet.cpp` `DieTouch`, halflife-updated's
  check). SDK 2.3 passed the missing owner to TakeDamage.
- **`GetSequenceFlags` and `SetBlending` keep halflife-updated's sequence range checks**
  (`dlls/animation.cpp`), as `GetSequenceInfo` does; an LCS `seq` token can set a negative one.
  (Could fold into the existing `GetSequenceInfo` line.)
- **sentences.txt and keyvalue parsing stay in their buffers** (halflife-updated's): `SENTENCEG_Init`
  stops at the last sentence slot instead of one past it, `UTIL_StringToVector` and
  `UTIL_StringToIntArray` copy at most 127 characters, `UTIL_StripToken` stops at its destination's size,
  and `UTIL_SetOrigin` skips a NULL edict (`dlls/sound.cpp`, `dlls/util.cpp`).

Elsewhere (a "Kept from halflife-updated" note, if wanted):

- **`TEXTURETYPE_Init` reads materials.txt from its start** (`dlls/sound.cpp`). SDK 2.3 (and so RC2)
  left `filePos` uninitialized; the original read the file from whatever its stack held.
- **Save/restore is halflife-updated's** (`dlls/cbase.cpp` Dispatch*/Save*Fields, `dlls/util.cpp`
  CSave/CRestore): reference-held save data, bool and int64 fields, 64-bit function pointers, alien
  slave beams not saved. Multiplayer doesn't save.

## Odd

- `scripts/stock_drift.py` silently skips a function whose signature line carries a trailing
  comment that doesn't end in `)`, such as `// orig 0xc3eb0`: its body regex needs `)` then `{`. In my
  files that hid the 10 functions in the second table (one, FindEntity, carries part of the play
  change). Across the tree my comment-stripping copy reports 402 rows against the tsv's 400: those 10
  added, and 7 rows in other packages' files not reported (`CHalfLifeMultiplay::CHalfLifeMultiplay`,
  `CHalfLifeMultiplay::RefreshSkillData`, `CMultiManager::KeyValue`, `CMultiManager::Spawn`,
  `CRenderFxManager::Use`, `CWeaponBox::KeyValue`, `CWeaponBox::GiveAmmo`). Those 7 are probably my
  copy's fault (naive stripping eats `//` inside string literals), so the tsv's rows stand; the other
  packages may still want to run it for misses of their own.
- The free-function lookup also lands on the wrong file: 0x9b00 `ExtractBbox` is in animation.cpp (the
  tsv says animating.cpp), 0x1a350 `SetObjectCollisionBox` is cbase.cpp's free one (the tsv says
  agrunt.cpp, so a2 or whoever owns agrunt.cpp may have audited CAGrunt's inline member under that
  rva), and 0xce8a0 `memfgets` was diffed against a call to it inside SENTENCEG_Init.
- `CEnvSound::KeyValue`: a fractional `roomtype` ("0.5") was nonzero in SDK 2.3's float and is 0 in our
  int. That only matters for a hand-written value, since FGDs give integers, so I kept it as style.
- `CEnvSound::Think` (not stock, already reconstructed as SDK 2.3) leaves sending the room type to
  `CBasePlayer::UpdateClientData`, which is halflife-updated's arrangement. Not mine to judge here, but
  whoever owns player.cpp may want to check it against SDK 2.3's direct SVC_ROOMTYPE.
