### The unclear ones

- **CScientist::Precache, CDeadScientist::Spawn** (and CScientist::Spawn, CSittingScientist, not
  rows here): the model is `_sv_override_scientist_mdl` when that cvar holds a name longer than 5
  characters, else `models/scientist.mdl`. Our dll doesn't register the cvar; whether today's engine
  does (HL25 added it for Uplink) decides whether an admin can set it at all. At its default
  nothing changes. Reverting means all four sites together (Spawn's SET_MODEL needs Precache's
  model), so either revert all or list the cvar beside the others in DEVIATIONS.md.
- **AddAmmoNameToAmmoRegistry**: only stores data. Its reader is `CBasePlayer::GiveAmmo`
  (`dlls/player.cpp`, a3's file), which gives an exhaustible weapon (grenades, satchels, ...)
  along with its ammo when the player lacks it. That reader is play; if a3 reverts it, this field
  is dead and can go.
- **CanAttack**: a server-client sync fix (halflife issue #1621, halflife-updated 343ebf2). The
  predicted branch now lets a weapon fire when its next attack is under 1 ms away, matching what
  the client predicts from millisecond-rounded times. In play it changes only whether the server
  agrees with a shot the client already predicted; the original had the mismatch. Timing, but by
  less than a millisecond, and it is in shared client code.

## For DEVIATIONS.md

- **game_score and game_player_equip take a NULL activator, and game_player_equip's weapon keys
  are cut at 127 characters** (`dlls/maprules.cpp`). halflife-updated's guards, kept.
- **Node graphs go through the engine filesystem in the mod directory only**
  (`maps/graphs/<map>.nod`, `.nod64` on amd64; `dlls/nodes.cpp` FLoadGraph, FSaveGraph,
  CheckNODFile, and the build report). The original's LOAD_FILE_FOR_ME also found a graph in the
  fallback game directory.
- If Steven keeps them: `_sv_override_scientist_mdl` as a kept engine cvar with its readers in
  `dlls/scientist.cpp`; `CanAttack`'s millisecond rounding (`dlls/weapons_shared.cpp`); the
  exhaustible weapon given with its ammo (`AddAmmoNameToAmmoRegistry`, `GiveAmmo`).

## Odd

- `stock_drift.py`'s `body()` matched a call site for two free functions: in `rc2/suckmine.cpp`
  `if (UTIL_AngleDiff(...) < 10 && fabs(...) < 10)` and in `rc2/gaussbecon.cpp` an `if` calling
  `UTIL_GetGlobalTrace()`, since `\([^;{]*\)` runs across the whole condition up to the `{`. The
  real bodies are in `dlls/util.cpp` (a4's file) and are SDK 2.3's. The tool still reports them as
  "not in base"; a function match that rejects a preceding `if (`/`&&` would drop both.
- `m_ForceSendAnimations` is also set around Deploy in `dlls/player.cpp` (lines ~4836 and ~6416,
  a3's file). With SelectLastItem reverted, those should get the same decision.
- doors.cpp's earlier comments said halflife-updated's door sound fix was kept on purpose (p2's
  reconstruction); that predates the 2026-11-07 decision and is now reverted, comments updated.
- SDK 2.3's `CNodeEnt::KeyValue` handles `hinttype` and then falls to the `else` of the
  `activity` test, so CBaseEntity::KeyValue clears fHandled again. Nothing reads fHandled after
  that for an entity, so halflife-updated's early return changes nothing.
- SDK 2.3's `LinkVisibleNodes` calls fprintf on its report file unguarded in two places; with a
  NULL file (report couldn't be opened) it crashes. Ours passes the invalid handle to the engine
  filesystem's FPrintf instead; I didn't check that the engine side rejects it.
